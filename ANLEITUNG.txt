RAUMSTEUERUNG SITZUNGSZIMMER 5 – EINRICHTUNG AUF DEM RAUM-PC
=============================================================

Inhalt des Pakets
-----------------
Raum5_Companion.companionconfig   Alle Companion-Buttons, Variablen, Verbindungen (OBS + RM-CR)
Raumsteuerung\                    Tablet-Seite + kleiner Webserver
  raumsteuerung.html              Die Tablet-Seite
  server.ps1                      Webserver (Port 8080)
  installieren.ps1                Richtet alles ein (als Administrator)
  deinstallieren.ps1              Entfernt Webserver, Mikrofon-Automatik und Firewall-Regeln
  mikro-automatik.ps1             Publikum-Kamera folgt dem Tischmikrofon (läuft im Hintergrund)
  mikro-automatik.json            Einstellungen dazu (Mikrofon -> Kanal, Schwellen, Zeiten)
  mikrofone-testen.cmd            Doppelklick: Pegel aller Kanäle live (Zuordnung herausfinden)
  pruefen.cmd                     Doppelklick: prüft Companion, OBS, RM-CR, Webserver, Netzwerk (ändert nichts)
Raum5_OBS_Szenen_Backup.json      OBS-Szenen (Stand 05.10., Platzhalter statt echter Quellen)


1. Yamaha RM-CR
---------------
- RM-CR per Netzwerk mit dem Raum-PC verbinden.
- Feste IP-Adresse prüfen (RM Device Finder). Im Test war es 192.168.137.185.
- RM-CR per USB anschließen und in Windows als Standard-Audiogerät einstellen
  (Wiedergabe UND Aufnahme). Dann geht der Ton aus Teams über den Prozessor.


2. OBS Studio
-------------
- OBS installieren und starten.
- Szenensammlung -> Importieren -> Raum5_OBS_Szenen_Backup.json auswählen,
  dann unter Szenensammlung die importierte Sammlung anklicken.
- Werkzeuge -> WebSocket-Servereinstellungen:
  * "WebSocket-Server aktivieren" anhaken
  * Port 4455
  * "Authentifizierung aktivieren" anhaken, Passwort notieren
- Die farbigen Platzhalter (Präsentation, Redner, Publikum) später durch
  die echten Quellen ersetzen (Elgato HD60 X, NDI-Kameras). Position bleibt gleich.
- OBS immer über Datei -> Beenden schließen, sonst gehen Änderungen verloren.


3. Bitfocus Companion
---------------------
- Companion installieren (gleiche Version oder neuer, getestet mit 5.0.6).
- Web-Oberfläche öffnen: http://127.0.0.1:8000
- VORHER die laufende Konfiguration sichern: Import / Export -> Export (Datei aufheben).
- Import / Export -> Raum5_Companion.companionconfig importieren (alles übernehmen).
  Enthält alle Buttons für Tablet und Mikrofon-Automatik (Seite 1 Steuerung, Seite 3 Kamera),
  die Variablen (r5_room, r5_pauto, r5_pmic, ...) und die Trigger.
- Connections -> obs -> Passwort von OBS eintragen (ist im Paket absichtlich leer).
- Connections -> rmcr -> IP-Adresse des RM-CR prüfen.
- Beide Verbindungen müssen grün sein.
- Settings: Companion beim Windows-Start automatisch starten lassen.
- Settings, Abschnitt HTTP: "HTTP API" muss eingeschaltet sein (Standard; Tablet und Automatik nutzen sie).


4. Webserver für das Tablet
---------------------------
- Ordner "Raumsteuerung" auf den Raum-PC kopieren.
- Rechtsklick auf installieren.ps1 -> "Mit PowerShell ausführen"
  (als Administrator; ggf. Admin-PowerShell öffnen und .\installieren.ps1 starten).
- Das Skript:
  * kopiert alles nach C:\Raumsteuerung
  * öffnet Port 8080 und 8000 in der Firewall (nur Domäne/Privat)
  * startet den Webserver automatisch bei jedem Systemstart
  * startet die Mikrofon-Automatik automatisch bei jedem Systemstart
  * zeigt am Ende die Adresse für das Tablet an, z. B. http://192.168.1.50:8080
- Die Seite findet Companion automatisch (gleicher PC, Port 8000).
- Wichtig: Der Raum-PC braucht eine feste IP-Adresse (oder DHCP-Reservierung).


5. Tablet
---------
- Tablet ins gleiche Netzwerk wie den Raum-PC bringen.
- Adresse aus Schritt 4 im Browser öffnen.

Android (Chrome):
- Menü (drei Punkte) -> "Zum Startbildschirm hinzufügen".
  Hinweis: Über http:// (ohne https) legt Chrome nur eine Verknüpfung an, keine echte App.
  Die Seite schaltet deshalb beim ersten Antippen selbst in den Vollbildmodus.
  Für Dauerbetrieb besser: App "Fully Kiosk Browser" (Startseite = Adresse aus Schritt 4,
  Kiosk-Modus an, Bildschirm immer an). Dann kann niemand die Seite verlassen.
- Einstellungen -> Sicherheit -> "App anheften" einschalten, App öffnen und anheften.
  So kann niemand die Seite aus Versehen verlassen.
- Display: Bildschirm-Timeout auf "nie" oder lange Zeit; Tablet am Ladegerät lassen.
- Anderer Companion-PC: einmalig  http://<Adresse>:8080/?companion=http://<IP>:8000  öffnen
  (wird im Tablet gespeichert).

iPad (Safari):
- Teilen -> "Zum Home-Bildschirm".
- Einstellungen -> Bedienungshilfen -> Geführter Zugriff einschalten,
  App öffnen und dreimal die Seitentaste drücken.
- Automatische Sperre: "Nie".


6. Test nach der Einrichtung
----------------------------
Zuerst C:\Raumsteuerung\pruefen.cmd doppelklicken: alles grün = Technik läuft, sonst steht dort, was zu tun ist.
[ ] Raum starten -> Virtual Cam läuft, oben steht "Live in Teams"
[ ] Alle 5 Ansichten tippen -> OBS wechselt die Szene
[ ] Lautstärke + / - -> Lautsprecher werden leiser / lauter
[ ] Hilfe -> "Ton zurücksetzen" -> Ton an, mittlere Lautstärke
[ ] In OBS direkt Szene wechseln -> Tablet zeigt nach ca. 3 Sekunden die richtige Ansicht
[ ] Raum ausschalten -> Abfrage, danach Startbildschirm
[ ] Companion beenden -> Tablet zeigt Hinweis "Keine Verbindung zum Raum-PC",
    die Live-Kachel zeigt "Status unbekannt"
[ ] Kamera: Pfeil gedrückt halten -> Kamera fährt, loslassen -> Kamera stoppt
[ ] Publikum-Kamera auf "Automatisch", dann Pfeil drücken -> Automatik geht aus
[ ] Raum am Stream Deck ausschalten -> Tablet springt auf den Startbildschirm
    (nur wenn Companion die Variable r5_room setzt, siehe unten)


Bei Problemen: IT-Service 2020


7. Mikrofon-Automatik (Publikum-Kamera folgt dem Tischmikrofon)
-----------------------------------------------------------------
So funktioniert es: mikro-automatik.ps1 liest die Pegel vom RM-CR (Meter RM:NeInPostFader)
und drückt in Companion den passenden Publikum-Button. Regeln:
  - ein Mikrofon spricht (mind. 0,4 s)  -> Zone dieses Mikrofons
  - zwei gleichzeitig                    -> Ganzer Raum
    (ausser eines ist deutlich lauter, "vorsprungStufen", Standard 8 -> dessen Zone;
     so stoert ein Nachbarmikrofon nicht, das dieselbe Stimme leiser mithoert)
  - 3 s Stille                           -> Ganzer Raum
  - höchstens eine Bewegung alle 4 s; Husten/Klopfen (< 0,4 s) wird ignoriert
  - Wortwechsel zwischen zwei Mikrofonen schaltet direkt um (kein Umweg über "Ganzer Raum")
  - nur wenn auf dem Tablet "Automatisch" an ist (r5_pauto = 1)
Mikrofon -> Zone: 1 -> 3/1/1 (Reihe 1-2 links), 2 -> 3/1/2, 3 -> 3/1/3, 4 -> 3/1/4, 5 -> 3/1/3.

a) Zuordnung herausfinden
   - C:\Raumsteuerung\mikrofone-testen.cmd doppelklicken.
   - Nacheinander in Mikrofon 1, 2, ... sprechen. Der Kanal mit "<-- SPRICHT" gehört dazu.
     Spitze = höchster Wert der letzten 3 s. 7E = 0 dBFS.
   - Grundrauschen ohne Sprache notieren (im Test ca. 61). Es muss unter "schwelleAusHex" liegen.
   - In mikro-automatik.json eintragen, z. B. "1": [1], "2": [2]
     (liefert ein RM-TT zwei Kanäle: "1": [1, 2]). Nicht vorhandene Mikrofone: [].
   - Schwellen anpassen: "schwelleHex" = Sprache sicher darüber (Standard 6C),
     "schwelleAusHex" etwas niedriger (Standard 68).
   - Danach die Aufgabe neu starten: Aufgabenplanung -> "Raumsteuerung Mikrofon-Automatik"
     -> Beenden, Ausführen (oder PC neu starten).
   - Alternative zum Testen: Meter "RM:NeInAutomixGain" (zeigt, wem der Automixer das Wort gibt).

b) Companion (ist in Raum5_Companion.companionconfig schon enthalten)
   - Variablen r5_pauto (1 = Automatik an) und r5_pmic (sprechendes Mikrofon).
   - Buttons 3/1/6 / 3/1/7: Automatik an / aus.
   - Buttons 3/1/1 bis 3/1/5: setzen r5_ppreset. Sobald die Publikum-Kamera da ist,
     dort zusätzlich "Preset abrufen" der Kamera eintragen.
   - Optional Bild einfrieren beim Schwenk: Buttons 3/1/8 (Freeze an) und 3/1/9 (Freeze aus)
     mit OBS-Aktion "Filter sichtbar" auf der Publikum-Quelle (Freeze-Filter-Plugin nötig),
     dann in mikro-automatik.json "freezeAn": "3/1/8", "freezeAus": "3/1/9".

c) Prüfen
   - Companion-Verbindung "rmcr" muss grün bleiben, während die Automatik läuft
     (das Skript hat eine eigene RCP-Verbindung zum RM-CR).
   - Protokoll: C:\Raumsteuerung\mikro-automatik.log (wer spricht, welcher Button gedrückt wurde).
   - Ohne Kamera gefahrlos testen: in Admin-PowerShell
       C:\Raumsteuerung\mikro-automatik.ps1 -Trocken
     (zeigt nur an, was es tun würde; vorher die Aufgabe beenden).
   - Tablet, Kamera-Seite: das sprechende Mikrofon leuchtet grün.


8. Wenn die fehlende Hardware kommt – wo in Companion ergänzen
----------------------------------------------------------------
Die Buttons gibt es schon; sie setzen bisher nur die Zustandsvariable.
Jeweils die Geräte-Aktion in den Button dazulegen (Tablet muss nicht geändert werden):
  HDMI-Matrix (TESmart)      1/2/1 Raum-PC, 1/2/2 Laptop, 1/2/3 Kabellos
  Präsentation ausblenden    1/2/4 aus, 1/2/5 an
  Displays (ViewSonic, LAN)  1/2/6 an, 1/2/7 aus, 1/3/7 "Displays neu starten"
                             und in 1/0/1 (Raum an) / 1/0/2 (Raum aus)
  Redner-Kamera              3/0/1-3 Presets, 3/2/1-6 Bewegung (Taste DRÜCKEN = fahren,
                             LOSLASSEN = stoppen), 3/2/7 Grundstellung, 1/3/3-4 Tracking
  Publikum-Kamera            3/1/1-5 Presets, 3/3/1-6 Bewegung, 3/3/7 Grundstellung
Danach den Test aus Abschnitt 6 wiederholen.

Trigger "Raum 5: Auto-Aus nach 2 h (Sicherheitsnetz)": schaltet den Raum (Button 1/0/2) aus,
wenn 2 h 10 min niemand etwas bedient hat. Normalerweise fragt vorher das Tablet
("Wird der Raum noch genutzt?"); "Weiter nutzen" meldet sich über Button 1/3/8 bei Companion.

9. Teams vom Tablet aus bedienen (Mikro, Bild, Verlassen)
-----------------------------------------------------------
Auf der Steuerung erscheint oben eine Teams-Leiste, sobald auf dem Raum-PC ein Teams-Meeting offen ist:
"Mikro an/aus", "Bild an/aus", "Verlassen" (Verlassen erst nach zweitem Tippen).
So funktioniert es: teams-steuerung.ps1 liest und drückt die Buttons im Teams-Meetingfenster
über Windows UI Automation (wie ein Bildschirmleser). Keine Teams-API, kein Teams-Admin nötig.
  - Companion-Buttons 1/0/4 (Mikro), 1/0/5 (Bild), 1/0/6 (Verlassen) setzen r5_tcmd = mute/video/leave.
  - Das Skript meldet r5_t_in (Meeting offen), r5_t_mute (stumm), r5_t_video (Bild an) zurück.
Einrichtung:
  a) installieren.ps1 legt die Aufgabe "Raumsteuerung Teams-Steuerung" an. Sie startet bei jeder
     Windows-Anmeldung im Benutzerkonto (nicht als SYSTEM - sie braucht den Desktop).
     Raum-PC: automatische Anmeldung des Raum-Kontos einrichten, sonst läuft sie erst nach Anmeldung.
  b) Nach der Installation einmal ab- und wieder anmelden.
  c) Test: Teams-Meeting starten -> Tablet zeigt die Leiste. "Mikro" tippen -> Teams schaltet stumm.
     Ohne Tablet: C:\Raumsteuerung	eams-steuerung.ps1 -Status   bzw.  -Befehl mute
  d) Protokoll: C:\Raumsteuerung	eams-steuerung.log
Grenzen: Teams kennt keinen auslesbaren Zustand für "Hand heben" - deshalb keine Hand-Taste.
Organisator übergeben, Wartebereich, andere stummschalten: nur in Teams selbst.
Nach großen Teams-Updates kann eine Button-Kennung wechseln (microphone-button, video-button,
hangup-button) - dann in teams-steuerung.ps1 ($IDS) anpassen.
